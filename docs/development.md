## Toolchain

- **Go 1.26.8+** for the service and DM520 cross-compilation.
- **Node.js 20+** for browser-module regression tests.
- **Python 3** for the plugin harness; Python 2.7 is also tested in Docker.
- **Docker** for the virtual receiver (OrbStack works on macOS).
- **Google Chrome** for `make docs`, which prints the Windows HTML guide to PDF.

The compiler version matters on old receiver kernels. Go 1.26.0 crashed with `futexwakeup ... returned -89` on the real DM520's Linux 3.4 kernel even though the executable ran in QEMU. Go 1.26.8 was verified on that receiver.

## Everyday commands

```sh
make dev          # local service on :8088; receiver files under ./dev
make test         # go vet, Go tests and Node receiver-editor tests
make box          # Linux MIPS little-endian, soft-float executable
make ipk          # dist/dreaminator_<version>_all.ipk
make box-vuuno4kse # static Linux ARMv7 binary in dist/vuuno4kse/dreaminator
make ipk-vuuno4kse # dist/dreaminator_<version>_vuuno4kse.ipk (experimental)
make deploy HOST=192.168.1.45  # build and install over SSH
make logs         # receiver log, using HOST
make icons        # regenerate application icons
make ui-assets    # regenerate native TV artwork from ui_theme.py
make docs         # printable Windows guide
```

`make dev` uses local directories and disables OpenWebif. The web interface is plain HTML, CSS and JavaScript embedded with Go's `embed`; it has no frontend build step. Local tests can load playlists and EPG using `file:///absolute/path` URLs. The package version defaults to the Makefile's `VERSION`; override it explicitly when preparing a different build.

The Vu+ target uses `GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0`. Its static executable has no dependency on the image's libc or an ARM cross-compiler. The IPK declares `Architecture: vuuno4kse`, the receiver's machine architecture, so normal `opkg` architecture checks distinguish it from a DM520 package. The packager checks ELF class, byte order, CPU and static linking before creating either package. `Architecture: all` remains the legacy DM520 label for compatibility; it is not a universal executable.

Run both `make ipk` and `make ipk-vuuno4kse` to produce the packages side by side. `make deploy HOST=...` always builds and deploys the **DM520** package; use the [manual Vu+ installation](installation.md#vu-uno-4k-se--openatv-75-experimental) for the ARM package. The existing simulator emulates DM520/MIPS, so a passing simulator run alone does not validate the ARM executable or openATV hardware behavior.

## Virtual Dreambox

```sh
make sim          # build the package and start the Docker simulator
make plugin-test  # Python 3 and 2.7 harness plus simulator API integration
make sim-logs     # container log
make sim-stop     # stop the container
make sim-reset    # remove simulator state and volumes
```

- `http://localhost:8088`: the tablet interface.
- `http://localhost:8090`: a simulated TV with bouquets, infobar, HLS/MPEG-TS playback proxy, bouquet format validation, EPGImport and logs.
- `dist/plugin-preview.html`: plugin screen previews generated by the harness.

The simulator unpacks the **same `.ipk`**, then runs its MIPS executable through QEMU with `-cpu 4Kc` (MIPS32 without an FPU). It has no system certificates. `tools/fakebox` emulates OpenWebif's `statusinfo`, `servicelistreload`, `zap` and `powerstate`, strictly parses bouquets, and repeats EPGImport's mapping flow.

Add a Stalker source at `http://127.0.0.1/stalker_portal/c/` with a MAC beginning `00:1A:79` for the demo portal. The catalog integration harness uses a separate demo category with 60 movies, metadata, posters and server search. The archive fixture is at `http://127.0.0.1/archive/playlist.m3u` and models sliding HLS and finite VOD recordings. The local `dev/` directory is mounted as `/media/dev`, so fixtures can use `file:///media/dev/demo.m3u`.

The plugin harness replaces Enigma2 modules with stubs, exercises remote actions, stale callbacks, source isolation, all three Stalker series modes, fresh playback links and return navigation. It runs on Python 2.7 and Python 3. It cannot certify the receiver's actual player, GUI, Linux 3.4 kernel, codec support, HDMI audio, physical remote or installed EPGImport version. Track those checks separately in the roadmap.

## Architecture

```text
Tablet / computer browser              TV / remote
          | HTTP :8088                      | Enigma2 plugin
          v                                 v
Dreambox: /usr/bin/dreaminator (Go service + embedded web interface)
  |-- M3U / Xtream / Stalker -> source caches and selected lists
  |-- native catalog API -> Python plugin -> Enigma2 MoviePlayer
  |-- bouquets -> /etc/enigma2 -> OpenWebif reload / zap
  |-- XMLTV -> filtered EPG + compact guide indexes -> EPGImport
  |-- provider artwork -> picons / native ePicLoad poster decoding
  `-- optional TMDB -> metadata and pre-shaded backdrops
```

Managed IPTV service references use stable SID/TSID values derived from the source and channel, with ONID `1DE`, so EPGImport can map programmes to them. Synchronization writes `userbouquet.dreaminator_*` files and retains unrelated bouquet index entries. The separate receiver editor changes an external bouquet only when explicitly saved.

Stalker bouquet URLs point to `http://127.0.0.1:8088/stalker/<source>/<channel>`. The service obtains a fresh `create_link` URL and redirects the player; the media stream goes directly to the player. Portal sessions are retained and renewed once on authorization failure; a watchdog reports activity while viewing. HTTPS uses embedded Go root certificates to support images with outdated system roots.

## Source map

| Path | Responsibility |
| --- | --- |
| `cmd/dreaminator` | Service entry point and flags |
| `internal/app` | State, sources, lists, catalog, library, EPG and overnight updates |
| `internal/playlist` | M3U parsing, archive URLs and Xtream live TV |
| `internal/stalker` | Portal client; `stalkertest` provides fixtures and the demo portal |
| `internal/tmdb` | Matching, API client and metadata caches |
| `internal/epg` | Streaming XMLTV filter and compact programme indexes |
| `internal/probe` | HTTP/HLS stream checks and MPEG-TS codec detection |
| `internal/picon` | Logo conversion and receiver picon directory selection |
| `internal/enigma` | Bouquets, OpenWebif and EPGImport files |
| `internal/server` | HTTP/JSON API and QR code |
| `web/static` | Tablet interface and application icons |
| `plugin/Dreaminator` | Native Enigma2 plugin, `ui_epgkey` / `ui_bouquet` bouquet integration and TV artwork |
| `plugin/DreaminatorEPG` | Separate EPG event-information/hotkey plugin entry |
| `tools/genicons`, `tools/genui` | Application and TV artwork generators |
| `packaging`, `tools/mkipk` | Init script and `.ipk` builder |
| `sim`, `tools/fakebox`, `tools/plugin-harness` | Virtual receiver and Python test harness |
| `docs` | User guides and engineering plans/specifications |

The TV plugin separates `ui_shell` (catalog), `ui_detail` (cards), `ui_guide` (daily guide), `ui_search`, `ui_widgets`, `ui_images`, `ui_models` (focus/paging without Enigma2) and `ui_theme`. Geist fonts are bundled under the [SIL Open Font License](../plugin/Dreaminator/fonts/OFL.txt). HD/FHD assets live in `ui/hd` and `ui/fhd`.

## Receiver files

| Path | Contents |
| --- | --- |
| `/usr/bin/dreaminator` | Service executable |
| `/etc/init.d/dreaminator` | Boot/service control |
| `/etc/dreaminator/` | Settings, source caches, uploads, filtered EPG and guide indexes |
| `/etc/dreaminator/library.json` | Movie/series favorites and recents |
| `/etc/dreaminator/receiver-undo/` | Receiver bouquet recovery snapshots |
| `/usr/lib/enigma2/python/Plugins/Extensions/Dreaminator/` | Enigma2 plugin |
| `/usr/share/enigma2/picon/` or detected picon directory | Managed channel logos |
| `/tmp/dreaminator.log` | RAM-backed log, cleared on reboot |

State is written atomically with file/directory synchronization and a previous-version `.bak`. Corrupt files are retained as `.broken-…` for recovery. Catalog artwork uses bounded memory and `/tmp` files instead of repeated flash writes.

## Contributing

Include the receiver model, image/build, Python version and Dreaminator version in a bug report. Describe how to reproduce the problem and attach redacted logs. Distinguish simulator results from real receiver checks. For changes, run the relevant checks and `make test`; native plugin changes also need `make sim` and `make plugin-test`. Before pushing a PR branch, follow the repository owner's local Codex and Greptile review requirements.
